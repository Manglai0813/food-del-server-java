# フェーズ 1: 基盤構築 - 詳細設計書

### 2. データベース接続と JPA 設定

#### 2.1 データベース接続設定

**目的**: PostgreSQL への接続を確立

**設定項目**:
- データソース設定（URL、ユーザー名、パスワード）
- 接続プール設定（HikariCP）
- 接続タイムアウト設定

**実装場所**:
- `application.yml` の `spring.datasource` セクション
- または `@Configuration` クラスで `DataSource` Bean を定義

**設定例**:
```yaml
spring:
  datasource:
    url: jdbc:postgresql://localhost:5432/food_delivery
    username: postgres
    password: ${DB_PASSWORD}
    driver-class-name: org.postgresql.Driver
    hikari:
      maximum-pool-size: 10
      minimum-idle: 5
      connection-timeout: 30000
```

#### 2.2 JPA 設定

**目的**: JPA/Hibernate の動作設定

**設定項目**:
- DDL モード（開発: `update`、本番: `validate`）
- SQL ログ出力設定
- 命名戦略
- 遅延ロード設定

**実装場所**:
- `application.yml` の `spring.jpa` セクション

**設定例**:
```yaml
spring:
  jpa:
    hibernate:
      ddl-auto: update
    show-sql: true
    properties:
      hibernate:
        format_sql: true
        dialect: org.hibernate.dialect.PostgreSQLDialect
        naming:
          physical-strategy: org.hibernate.boot.model.naming.PhysicalNamingStrategyStandardImpl
```

#### 2.3 トランザクション管理設定

**目的**: トランザクションの動作設定

**設定内容**:
- デフォルトのトランザクション分離レベル
- トランザクションタイムアウト
- 読み取り専用トランザクションの設定

**実装方法**:
- `@EnableTransactionManagement` アノテーション
- `PlatformTransactionManager` Bean の設定（必要に応じて）

### 3. エンティティクラスの定義

#### 3.1 Prisma スキーマからの変換

**目的**: 既存の Prisma スキーマを JPA エンティティに変換

**変換対象テーブル**:
- User（ユーザー）
- Category（カテゴリ）
- Food（商品）
- Cart（カート）
- CartItem（カートアイテム）
- Order（注文）
- OrderItem（注文アイテム）
- OrderStatusHistory（注文ステータス履歴）
- InventoryHistory（在庫履歴）

#### 3.2 エンティティ設計原則

**基本アノテーション**:
- `@Entity`: エンティティクラスのマーク
- `@Table`: テーブル名の指定
- `@Id`: 主キーの指定
- `@GeneratedValue`: 主キー生成戦略
- `@Column`: カラム属性の指定

**リレーションシップ**:
- `@OneToOne`: 1対1の関係
- `@OneToMany`: 1対多の関係
- `@ManyToOne`: 多対1の関係
- `@ManyToMany`: 多対多の関係（このプロジェクトでは使用しない）

**楽観的ロック**:
- `@Version`: バージョンフィールド（Food エンティティ）

**監査機能**:
- `@CreatedDate`: 作成日時
- `@LastModifiedDate`: 更新日時
- `@EntityListeners(AuditingEntityListener.class)`: 監査リスナーの有効化

#### 3.3 実装例（Food エンティティ）

**主要フィールド**:
- id, name, description, price
- category_id（外部キー）
- image_path, status
- stock, reserved, min_stock（在庫管理）
- version（楽観的ロック）
- created_at, updated_at（監査）

**リレーション**:
- `@ManyToOne` Category（カテゴリ）
- `@OneToMany` CartItem（カートアイテム）
- `@OneToMany` OrderItem（注文アイテム）
- `@OneToMany` InventoryHistory（在庫履歴）

### 4. 統一レスポンス形式（ApiResponse）の実装

#### 4.1 ApiResponse クラスの設計

**目的**: すべての API レスポンスを統一形式で返却

**クラス構造**:
- `success`: Boolean（成功/失敗）
- `message`: String（メッセージ）
- `data`: T（ジェネリック型、実際のデータ）
- `errors`: List<String>（エラーリスト、オプション）
- `code`: String（エラーコード、オプション）

**実装方針**:
- ジェネリッククラス `ApiResponse<T>`
- 静的ファクトリーメソッド（`success()`, `error()`）
- Builder パターン（オプション）

#### 4.2 PaginatedResponse クラスの設計

**目的**: ページネーション対応のレスポンス

**クラス構造**:
- ApiResponse を継承
- `pagination`: PaginationInfo オブジェクト
  - page, limit, total, totalPages
  - hasNext, hasPrev

#### 4.3 レスポンス包装の実装方式

**方式選択**:
- **自動包装**: `ResponseBodyAdvice` を使用
- **手動包装**: Controller で明示的に `ApiResponse` を返す

**推奨**: 自動包装を基本とし、特殊ケース（ファイルダウンロード等）は手動処理

### 5. グローバル例外処理の実装

#### 5.1 GlobalExceptionHandler の実装

**目的**: すべての例外を統一形式で処理

**実装方法**:
- `@ControllerAdvice` アノテーション
- `@ExceptionHandler` で例外タイプごとに処理

**処理対象例外**:
- `BusinessException`: ビジネス例外
- `ValidationException`: バリデーション例外
- `AuthenticationException`: 認証例外
- `AccessDeniedException`: 認可例外
- `MethodArgumentNotValidException`: 引数検証例外
- `Exception`: その他の例外（フォールバック）

#### 5.2 カスタム例外クラスの定義

**例外階層**:
- `BusinessException`（基底クラス）
  - `StockException`（在庫関連）
  - `OrderException`（注文関連）
  - `UserException`（ユーザー関連）
  - `NotFoundException`（リソース未検出）

**例外設計原則**:
- HTTP ステータスコードを含む
- エラーコードを含む
- ユーザーフレンドリーなメッセージ

#### 5.3 例外レスポンス形式

**レスポンス構造**:
- `success: false`
- `message`: エラーメッセージ
- `code`: エラーコード
- `errors`: フィールドエラーリスト（バリデーション時）

### 6. セキュリティ基盤（Spring Security 設定）

#### 6.1 SecurityConfig の基本設定

**目的**: Spring Security の基本設定

**設定内容**:
- 認証・認可の無効化（後で実装するため、一時的に無効化）
- CORS 設定
- セキュリティヘッダー設定
- セッション管理設定

**実装場所**:
- `config/security/SecurityConfig.java`

#### 6.2 CORS 設定

**目的**: クロスオリジンリクエストの許可

**設定内容**:
- 許可するオリジン（開発環境: localhost:3000, localhost:3001）
- 許可する HTTP メソッド
- 許可するヘッダー
- 認証情報の許可

#### 6.3 セキュリティヘッダー設定

**目的**: セキュリティ関連の HTTP ヘッダーを設定

**設定内容**:
- X-Content-Type-Options
- X-Frame-Options
- X-XSS-Protection
- Strict-Transport-Security（HTTPS 時）
