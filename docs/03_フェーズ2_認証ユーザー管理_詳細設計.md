# フェーズ 2: 認証・ユーザー管理機能 - 詳細設計書

## 概要

JWT トークンベースの認証システムとユーザー管理機能を実装するフェーズです。既存の TypeScript サーバーと互換性を保ちながら、Spring Security を活用した認証・認可システムを構築します。

## 実装タスク

### 1. JWT トークン管理の実装

#### 1.1 JWT ライブラリの選定

**選択肢**:
- **jjwt** (Java JWT): 軽量で使いやすい
- **Nimbus JOSE + JWT**: 機能豊富だが複雑

**推奨**: jjwt（シンプルで十分）

**依存関係**:
```xml
<dependency>
    <groupId>io.jsonwebtoken</groupId>
    <artifactId>jjwt-api</artifactId>
    <version>0.12.3</version>
</dependency>
```

#### 1.2 JwtTokenProvider の実装

**目的**: JWT トークンの生成・検証を行うユーティリティクラス

**主要メソッド**:
- `generateToken(UserDetails user)`: アクセストークン生成
- `generateRefreshToken(Long userId)`: リフレッシュトークン生成
- `validateToken(String token)`: トークン検証
- `getUserIdFromToken(String token)`: トークンからユーザーID取得
- `getExpirationDateFromToken(String token)`: 有効期限取得

**トークンペイロード**:
- Access Token: `id`, `email`, `role`, `iat`, `exp`
- Refresh Token: `userId`, `iat`, `exp`

**設定項目**:
- JWT Secret（環境変数から取得）
- Access Token 有効期限: 7日
- Refresh Token 有効期限: 30日

#### 1.3 トークン設定の管理

**実装場所**:
- `application.yml` または環境変数

**設定例**:
```yaml
jwt:
  secret: ${JWT_SECRET}
  refresh-secret: ${JWT_REFRESH_SECRET}
  access-token-validity: 604800000  # 7日（ミリ秒）
  refresh-token-validity: 2592000000  # 30日（ミリ秒）
```

### 2. ユーザー登録・ログイン機能

#### 2.1 UserService の実装

**インターフェース**: `UserService`
**実装クラス**: `UserServiceImpl`

**主要メソッド**:
- `register(RegisterRequest request)`: ユーザー登録
- `login(LoginRequest request)`: ログイン
- `findByEmail(String email)`: メールアドレスで検索
- `findById(Long id)`: ID で検索

#### 2.2 ユーザー登録機能

**処理フロー**:
1. メールアドレスの重複チェック
2. パスワード強度検証
3. パスワードハッシュ化（BCrypt）
4. ユーザーエンティティの作成
5. データベースに保存
6. レスポンス返却（パスワードは含めない）

**バリデーション**:
- メールアドレス形式チェック
- パスワード強度チェック（最小8文字、英数字含む）
- 名前の必須チェック

**DTO**:
- `RegisterRequest`: 登録リクエスト
- `AuthResponse`: 認証レスポンス（トークン + ユーザー情報）

#### 2.3 ログイン機能

**処理フロー**:
1. メールアドレスでユーザー検索
2. ユーザー存在チェック
3. パスワード検証（BCrypt）
4. JWT トークン生成（Access + Refresh）
5. レスポンス返却（トークン + ユーザー情報）

**DTO**:
- `LoginRequest`: ログインリクエスト（email, password）
- `AuthResponse`: 認証レスポンス

**エラーハンドリング**:
- ユーザー不存在: 404
- パスワード不一致: 401
- その他のエラー: 500

### 3. トークンリフレッシュ機能

#### 3.1 RefreshTokenService の実装

**目的**: リフレッシュトークンによるアクセストークンの更新

**処理フロー**:
1. リフレッシュトークンの検証
2. トークンからユーザーID取得
3. ユーザー存在確認
4. 新しいアクセストークン生成
5. レスポンス返却

**DTO**:
- `RefreshTokenRequest`: リフレッシュトークンリクエスト
- `TokenRefreshResponse`: トークン更新レスポンス

**エラーハンドリング**:
- トークン無効: 401
- トークン期限切れ: 401
- ユーザー不存在: 404

### 4. プロフィール管理機能

#### 4.1 プロフィール取得

**エンドポイント**: `GET /api/users/profile`

**処理フロー**:
1. JWT トークンからユーザーID取得（認証ミドルウェア）
2. ユーザー情報取得
3. レスポンス返却

**認証**: 必須（`@PreAuthorize("isAuthenticated()")`）

#### 4.2 プロフィール更新

**エンドポイント**: `PUT /api/users/profile`

**処理フロー**:
1. 認証チェック
2. リクエストバリデーション
3. ユーザー情報更新
4. レスポンス返却

**更新可能フィールド**:
- name（名前）
- phone（電話番号）

**DTO**:
- `UpdateProfileRequest`: プロフィール更新リクエスト
- `UserResponse`: ユーザー情報レスポンス

### 5. パスワード変更機能

#### 5.1 パスワード変更処理

**エンドポイント**: `POST /api/users/auth/change-password`

**処理フロー**:
1. 認証チェック
2. 現在のパスワード検証
3. 新しいパスワード強度検証
4. パスワードハッシュ化
5. パスワード更新
6. レスポンス返却

**DTO**:
- `ChangePasswordRequest`: パスワード変更リクエスト
  - currentPassword（現在のパスワード）
  - newPassword（新しいパスワード）

**エラーハンドリング**:
- 現在のパスワード不一致: 400
- パスワード強度不足: 400

### 6. ロールベースアクセス制御

#### 6.1 ユーザーロール定義

**ロール種類**:
- `ROLE_CUSTOMER`: 一般ユーザー
- `ROLE_STAFF`: スタッフ
- `ROLE_ADMIN`: 管理者

**実装方法**:
- `UserDetails` インターフェースの実装
- `GrantedAuthority` でロールを表現

#### 6.2 認可アノテーション

**使用アノテーション**:
- `@PreAuthorize("hasRole('ADMIN')")`: 管理者のみ
- `@PreAuthorize("hasAnyRole('ADMIN', 'STAFF')")`: 管理者またはスタッフ
- `@PreAuthorize("isAuthenticated()")`: 認証済みユーザー

**設定**:
- `@EnableMethodSecurity` でメソッドセキュリティを有効化

#### 6.3 カスタム UserDetailsService

**目的**: ユーザー情報を Spring Security に提供

**実装内容**:
- `loadUserByUsername(String email)`: メールアドレスでユーザー検索
- `UserDetails` オブジェクトの返却

---

### 7. JWT 認証フィルターの実装

#### 7.1 JwtAuthenticationFilter の実装

**目的**: リクエストから JWT トークンを抽出し、認証情報を設定

**処理フロー**:
1. リクエストヘッダーから `Authorization: Bearer <token>` を抽出
2. トークンの検証
3. トークンからユーザー情報取得
4. `Authentication` オブジェクトを作成
5. `SecurityContext` に設定

**実装場所**:
- `security/filter/JwtAuthenticationFilter.java`

**フィルター順序**:
- `UsernamePasswordAuthenticationFilter` の前に実行

#### 7.2 SecurityConfig の更新

**設定内容**:
- JWT フィルターの追加
- 認証不要エンドポイントの設定
- 認証必要エンドポイントの設定

**認証不要エンドポイント**:
- `POST /api/users/auth/register`
- `POST /api/users/auth/login`
- `POST /api/users/auth/refresh`

**認証必要エンドポイント**:
- その他のすべての `/api/**` エンドポイント

## 実装順序

1. **JWT トークンプロバイダー** → トークン生成・検証の実装
2. **UserService** → ユーザー管理サービスの実装
3. **認証 Controller** → 登録・ログイン・リフレッシュエンドポイント
4. **JWT 認証フィルター** → リクエスト認証の実装
5. **SecurityConfig 更新** → 認証・認可設定
6. **プロフィール管理** → プロフィール取得・更新
7. **パスワード変更** → パスワード変更機能

## 注意事項

1. **トークン秘密鍵**: 環境変数から取得し、コードに直接書かない
2. **パスワード**: 絶対にレスポンスに含めない
3. **トークン有効期限**: アクセストークンは短く、リフレッシュトークンは長く設定
4. **エラーメッセージ**: セキュリティを考慮し、詳細なエラー情報を返さない
5. **CORS**: 認証情報を含むリクエストを許可する設定
