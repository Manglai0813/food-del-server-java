# フェーズ 3: 商品・カテゴリ管理機能 - 詳細設計書

## 概要

商品とカテゴリの CRUD 操作、検索・フィルタリング、ページネーション機能を実装するフェーズです。

## 実装タスク

### 1. 商品 CRUD 操作

#### 1.1 FoodService の実装

**インターフェース**: `FoodService`
**実装クラス**: `FoodServiceImpl`

**主要メソッド**:
- `createFood(CreateFoodRequest request)`: 商品作成
- `updateFood(Long id, UpdateFoodRequest request)`: 商品更新
- `deleteFood(Long id)`: 商品削除
- `getFoodById(Long id)`: 商品詳細取得
- `getFoods(FoodSearchQuery query)`: 商品一覧取得（検索・フィルタリング）

#### 1.2 商品作成

**エンドポイント**: `POST /api/foods`（管理者のみ）

**処理フロー**:
1. 認証・認可チェック（管理者権限）
2. リクエストバリデーション
3. カテゴリ存在確認
4. 商品エンティティ作成
5. 画像アップロード処理（フェーズ 7 で実装）
6. データベース保存
7. レスポンス返却

**DTO**:
- `CreateFoodRequest`: 商品作成リクエスト
  - name, description, price
  - categoryId, imagePath
  - stock, minStock
  - status

**バリデーション**:
- name: 必須、最大長
- price: 必須、正の数
- categoryId: 必須、存在確認
- stock: 0以上
- minStock: 0以上

#### 1.3 商品更新

**エンドポイント**: `PUT /api/foods/:id`（管理者のみ）

**処理フロー**:
1. 認証・認可チェック
2. 商品存在確認
3. リクエストバリデーション
4. カテゴリ変更時の存在確認
5. 商品情報更新
6. レスポンス返却

**DTO**:
- `UpdateFoodRequest`: 商品更新リクエスト（CreateFoodRequest と同様、全フィールドオプション）

#### 1.4 商品削除

**エンドポイント**: `DELETE /api/foods/:id`（管理者のみ）

**処理フロー**:
1. 認証・認可チェック
2. 商品存在確認
3. 関連データチェック（注文、カートに使用されていないか）
4. 論理削除または物理削除（要件に応じて）
5. レスポンス返却

**注意**: 注文履歴に使用されている場合は削除不可

#### 1.5 商品詳細取得

**エンドポイント**: `GET /api/foods/:id`

**処理フロー**:
1. 商品存在確認
2. 商品情報取得（カテゴリ情報も含む）
3. レスポンス返却

**DTO**:
- `FoodResponse`: 商品情報レスポンス

---

### 2. 商品検索・フィルタリング

#### 2.1 検索クエリパラメータ

**パラメータ**:
- `keyword`: キーワード検索（商品名、説明）
- `categoryId`: カテゴリフィルタ
- `status`: ステータスフィルタ（true/false）
- `minPrice`: 最低価格
- `maxPrice`: 最高価格
- `page`: ページ番号（デフォルト: 1）
- `limit`: 1ページあたりの件数（デフォルト: 10）
- `sortBy`: ソート項目（price, name, created_at）
- `sortOrder`: ソート順（asc, desc）

#### 2.2 検索実装

**実装方法**:
- Spring Data JPA の `Specification` を使用
- 動的クエリの構築

**検索条件**:
- キーワード: `LIKE` 検索（商品名、説明）
- カテゴリ: `categoryId` でフィルタ
- ステータス: `status` でフィルタ
- 価格範囲: `BETWEEN` 検索

#### 2.3 公開商品一覧

**エンドポイント**: `GET /api/foods/public`

**処理内容**:
- `status = true` の商品のみ取得
- 認証不要

#### 2.4 注目商品取得

**エンドポイント**: `GET /api/foods/featured`

**処理内容**:
- 特定条件（例: 在庫あり、ステータス有効）の商品を取得
- 件数制限（例: 最大10件）

### 3. カテゴリ CRUD 操作

#### 3.1 CategoryService の実装

**インターフェース**: `CategoryService`
**実装クラス**: `CategoryServiceImpl`

**主要メソッド**:
- `createCategory(CreateCategoryRequest request)`: カテゴリ作成
- `updateCategory(Long id, UpdateCategoryRequest request)`: カテゴリ更新
- `deleteCategory(Long id)`: カテゴリ削除
- `getCategoryById(Long id)`: カテゴリ詳細取得
- `getCategories(CategorySearchQuery query)`: カテゴリ一覧取得

#### 3.2 カテゴリ作成

**エンドポイント**: `POST /api/categories`（管理者のみ）

**処理フロー**:
1. 認証・認可チェック
2. リクエストバリデーション
3. カテゴリ名の重複チェック
4. カテゴリエンティティ作成
5. データベース保存
6. レスポンス返却

**DTO**:
- `CreateCategoryRequest`: カテゴリ作成リクエスト
  - name（必須、ユニーク）
  - description（オプション）
  - status（デフォルト: true）

#### 3.3 カテゴリ更新

**エンドポイント**: `PUT /api/categories/:id`（管理者のみ）

**処理フロー**:
1. 認証・認可チェック
2. カテゴリ存在確認
3. リクエストバリデーション
4. カテゴリ名変更時の重複チェック
5. カテゴリ情報更新
6. レスポンス返却

#### 3.4 カテゴリ削除

**エンドポイント**: `DELETE /api/categories/:id`（管理者のみ）

**処理フロー**:
1. 認証・認可チェック
2. カテゴリ存在確認
3. 関連商品チェック（商品が紐づいている場合は削除不可）
4. 論理削除（status = false）または物理削除
5. レスポンス返却

#### 3.5 カテゴリ一覧取得

**エンドポイント**: `GET /api/categories`

**処理内容**:
- すべてのカテゴリを取得
- 認証不要

#### 3.6 アクティブカテゴリ取得

**エンドポイント**: `GET /api/categories/active`

**処理内容**:
- `status = true` のカテゴリのみ取得
- 認証不要

#### 3.7 カテゴリ別商品取得

**エンドポイント**: `GET /api/categories/:id/foods`

**処理内容**:
- 指定カテゴリに紐づく商品を取得
- ページネーション対応
- 認証不要

---

### 4. ページネーション機能

#### 4.1 ページネーション実装

**実装方法**:
- Spring Data JPA の `Pageable` を使用
- `Page<T>` または `Slice<T>` を返却

**パラメータ**:
- `page`: ページ番号（0始まりまたは1始まり）
- `size`: 1ページあたりの件数

#### 4.2 PaginatedResponse の構築

**処理内容**:
- `Page` オブジェクトから `PaginatedResponse` を構築
- ページネーション情報の計算
  - total: 総件数
  - totalPages: 総ページ数
  - hasNext: 次のページがあるか
  - hasPrev: 前のページがあるか

---

### 5. Entity-DTO 変換

#### 5.1 Mapper の実装

**実装方法**:
- MapStruct を使用（推奨）
- または手動で Converter クラスを作成

**変換対象**:
- `Food` Entity → `FoodResponse` DTO
- `Category` Entity → `CategoryResponse` DTO
- `CreateFoodRequest` DTO → `Food` Entity
- `UpdateFoodRequest` DTO → `Food` Entity

#### 5.2 変換時の注意点

- パスワードなどの機密情報は含めない
- リレーションシップのデータも適切に変換
- null チェックを適切に行う

---

## 実装順序

1. **CategoryService** → カテゴリ管理サービスの実装
2. **CategoryController** → カテゴリエンドポイントの実装
3. **FoodService** → 商品管理サービスの実装
4. **FoodController** → 商品エンドポイントの実装
5. **検索機能** → Specification を使用した動的検索
6. **ページネーション** → ページネーション機能の実装
7. **Mapper** → Entity-DTO 変換の実装
