# フェーズ 4: ショッピングカート機能 - 詳細設計書

## 概要

永続的なショッピングカート機能と在庫予約システムを実装するフェーズです。ユーザーが商品をカートに追加・削除し、在庫を予約する機能を提供します。

## 実装タスク

### 1. カート管理機能

#### 1.1 CartService の実装

**インターフェース**: `CartService`
**実装クラス**: `CartServiceImpl`

**主要メソッド**:
- `getCart(Long userId)`: カート取得
- `addToCart(Long userId, AddToCartRequest request)`: 商品追加
- `updateCartItem(Long userId, Long itemId, UpdateCartItemRequest request)`: カートアイテム更新
- `removeCartItem(Long userId, Long itemId)`: カートアイテム削除
- `clearCart(Long userId)`: カートクリア
- `calculateCartSummary(Cart cart)`: カートサマリー計算

#### 1.2 カート取得

**エンドポイント**: `GET /api/carts`

**処理フロー**:
1. 認証チェック
2. ユーザーID取得
3. カート取得（存在しない場合は作成）
4. カートアイテム取得（商品情報も含む）
5. カートサマリー計算
6. レスポンス返却

**DTO**:
- `CartResponse`: カート情報レスポンス
  - cartItems: カートアイテムリスト
  - summary: カートサマリー

#### 1.3 カートの自動作成

**処理内容**:
- ユーザー初回アクセス時にカートを自動作成
- `findOrCreateUserCart()` メソッドで実装

---

### 2. 商品追加・削除・更新

#### 2.1 商品追加

**エンドポイント**: `POST /api/carts/add`

**処理フロー**:
1. 認証チェック
2. リクエストバリデーション
3. 商品存在確認
4. 商品ステータス確認（有効か）
5. 在庫確認（利用可能在庫チェック）
6. カート取得または作成
7. 既存アイテムチェック
8. 在庫予約（InventoryService を使用）
9. カートアイテム作成または更新
10. レスポンス返却

**DTO**:
- `AddToCartRequest`: 商品追加リクエスト
  - foodId（必須）
  - quantity（必須、1以上）

**エラーハンドリング**:
- 商品不存在: 404
- 商品無効: 400
- 在庫不足: 400
- 数量不正: 400

#### 2.2 カートアイテム更新

**エンドポイント**: `PUT /api/carts/items/:id`

**処理フロー**:
1. 認証チェック
2. カートアイテム存在確認
3. 所有権確認（ユーザーのカートか）
4. 数量変更の計算
5. 数量増加時: 在庫予約
6. 数量減少時: 在庫予約解除
7. カートアイテム更新
8. レスポンス返却

**DTO**:
- `UpdateCartItemRequest`: カートアイテム更新リクエスト
  - quantity（必須、1以上）

#### 2.3 カートアイテム削除

**エンドポイント**: `DELETE /api/carts/items/:id`

**処理フロー**:
1. 認証チェック
2. カートアイテム存在確認
3. 所有権確認
4. 在庫予約解除（InventoryService を使用）
5. カートアイテム削除
6. レスポンス返却

#### 2.4 カートクリア

**エンドポイント**: `DELETE /api/carts/clear`

**処理フロー**:
1. 認証チェック
2. カート取得
3. すべてのカートアイテムの在庫予約解除
4. カートアイテム全削除
5. レスポンス返却

---

### 3. 在庫予約システムの実装

#### 3.1 在庫予約処理

**実装場所**: `InventoryService`（フェーズ 5 で詳細実装）

**処理内容**:
- カート追加時: `reserveStock()` を呼び出し
- カート削除時: `releaseReservation()` を呼び出し
- 数量変更時: 差分を計算して予約・解除

**注意点**:
- トランザクション内で実行
- 悲観的ロックを使用（`FOR UPDATE`）

#### 3.2 在庫確認

**処理内容**:
- 利用可能在庫 = stock - reserved
- 利用可能在庫 >= リクエスト数量 を確認

---

### 4. カートサマリー計算

#### 4.1 サマリー情報

**計算項目**:
- `itemCount`: 商品種類数
- `totalQuantity`: 総数量
- `totalAmount`: 合計金額

**計算方法**:
- カートアイテムをループ
- 各アイテムの数量 × 価格を合計

#### 4.2 実装

**メソッド**: `calculateCartSummary(Cart cart)`

**戻り値**: `CartSummary` オブジェクト

---

### 5. チェックアウト機能

#### 5.1 チェックアウト処理

**エンドポイント**: `POST /api/carts/checkout`

**処理フロー**:
1. 認証チェック
2. カート取得
3. カート空チェック
4. 注文作成処理（OrderService を使用、フェーズ 6 で実装）
5. カートクリア
6. レスポンス返却

**注意**: このフェーズでは基本的な処理のみ、詳細はフェーズ 6 で実装

## 注意事項

1. **在庫予約**: カート追加時に在庫を予約し、注文確定時に実際の在庫から減算
2. **トランザクション**: 在庫操作は必ずトランザクション内で実行
3. **楽観的ロック**: 在庫更新時の競合を防ぐため、楽観的ロックを使用
4. **カートの永続化**: ユーザーごとに1つのカートを保持
5. **価格の固定**: カート追加時の価格を保持（商品価格変更の影響を受けない）
