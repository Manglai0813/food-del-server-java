# フェーズ 5: 在庫管理システム - 詳細設計書

## 概要

在庫の更新、楽観的ロック・悲観的ロックによる並行制御、在庫予約・解除、在庫履歴記録を実装するフェーズです。

## 実装タスク

### 1. 在庫更新機能

#### 1.1 InventoryService の実装

**インターフェース**: `InventoryService`
**実装クラス**: `InventoryServiceImpl`

**主要メソッド**:
- `updateStock(Long foodId, Integer quantity, String operation, InventoryUpdateOptions options)`: 在庫更新
- `reserveStock(Long foodId, Integer quantity, Long userId, String note)`: 在庫予約
- `releaseReservation(Long foodId, Integer quantity, Long userId, String note)`: 予約解除
- `confirmReservation(Long foodId, Integer quantity, Long orderId, Long userId)`: 予約確定（注文確定時）
- `getStockInfo(Long foodId)`: 在庫情報取得

#### 1.2 在庫更新処理

**処理フロー**:
1. 商品存在確認
2. 楽観的ロックによる在庫取得
3. 在庫数計算（追加/減算）
4. 在庫数検証（0未満にならないか）
5. 予約在庫を超えないかチェック
6. バージョンチェック付き更新
7. 更新失敗時はリトライ（最大3回）
8. 在庫履歴記録

**操作タイプ**:
- `ADD`: 在庫追加
- `SUBTRACT`: 在庫減算

**楽観的ロック**:
- `@Version` アノテーションを使用
- `updateMany()` でバージョンチェック
- 更新失敗時は `OptimisticLockException` をスロー

---

### 2. 楽観的ロックの実装

#### 2.1 エンティティの設定

**Food エンティティ**:
- `@Version` アノテーションを `version` フィールドに追加
- 更新時に自動的にバージョンがインクリメント

#### 2.2 更新処理

**実装方法**:
- `updateMany()` でバージョンチェック
- `WHERE id = ? AND version = ?` 条件で更新
- 更新件数が0の場合は競合発生

**リトライロジック**:
- 最大3回リトライ
- リトライ間隔は指数バックオフ

---

### 3. 悲観的ロックの実装

#### 3.1 在庫予約処理

**実装方法**:
- `@Lock(LockModeType.PESSIMISTIC_WRITE)` を使用
- または `@Query` で `FOR UPDATE` を使用

**処理フロー**:
1. トランザクション開始
2. 悲観的ロックで商品取得
3. 利用可能在庫計算（stock - reserved）
4. 在庫確認
5. 予約在庫増加
6. 在庫履歴記録
7. トランザクションコミット

**使用箇所**:
- カート追加時の在庫予約
- 注文確定時の在庫確定

#### 3.2 予約解除処理

**処理フロー**:
1. トランザクション開始
2. 悲観的ロックで商品取得
3. 予約在庫確認
4. 予約在庫減少
5. 在庫履歴記録
6. トランザクションコミット

---

### 4. 在庫予約・解除機能

#### 4.1 在庫予約

**メソッド**: `reserveStock(Long foodId, Integer quantity, Long userId, String note)`

**処理内容**:
- `reserved` フィールドを増加
- `stock` は変更しない
- 在庫履歴に `RESERVE` タイプで記録

**戻り値**:
- `success`: 成功/失敗
- `availableStock`: 残りの利用可能在庫

#### 4.2 予約解除

**メソッド**: `releaseReservation(Long foodId, Integer quantity, Long userId, String note)`

**処理内容**:
- `reserved` フィールドを減少
- `stock` は変更しない
- 在庫履歴に `RELEASE` タイプで記録

#### 4.3 予約確定

**メソッド**: `confirmReservation(Long foodId, Integer quantity, Long orderId, Long userId)`

**処理内容**:
- 注文確定時に呼び出し
- `stock` と `reserved` を同時に減少
- 在庫履歴に `SUBTRACT` タイプで記録

**使用箇所**: フェーズ 6 の注文確定処理

---

### 5. 在庫履歴記録

#### 5.1 InventoryHistory エンティティ

**主要フィールド**:
- foodId: 商品ID
- changeType: 変更タイプ（ADD, SUBTRACT, RESERVE, RELEASE）
- quantity: 変更数量
- previousStock: 変更前在庫
- newStock: 変更後在庫
- orderId: 関連注文ID（オプション）
- createdBy: 変更実行者
- note: 備考

#### 5.2 履歴記録処理

**実装方法**:
- すべての在庫変更時に履歴を記録
- `recordInventoryChange()` メソッドで実装

**記録タイミング**:
- 在庫追加・減算時
- 在庫予約時
- 予約解除時
- 注文確定時

---

### 6. 在庫情報取得

#### 6.1 在庫情報

**取得項目**:
- `stock`: 総在庫
- `reserved`: 予約在庫
- `available`: 利用可能在庫（stock - reserved）
- `minStock`: 最小在庫閾値
- `isLowStock`: 低在庫フラグ（stock <= minStock）

**メソッド**: `getStockInfo(Long foodId)`

**戻り値**: `StockInfo` オブジェクト

## 注意事項

1. **トランザクション**: すべての在庫操作はトランザクション内で実行
2. **ロック選択**: 
   - 楽観的ロック: 手動在庫更新など、競合が少ない操作
   - 悲観的ロック: カート追加、注文確定など、競合が頻発する操作
3. **リトライ**: 楽観的ロック失敗時は自動リトライ（最大3回）
4. **在庫履歴**: すべての変更を記録し、監査可能にする
5. **パフォーマンス**: 大量の在庫操作時はパフォーマンスに注意
