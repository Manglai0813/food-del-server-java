# フェーズ 8: セキュリティ機能強化 - 詳細設計書

## 概要

レート制限、リクエストサイズ制限、セキュリティヘッダー、CORS 設定、リクエストタイムアウト、リクエスト監視・ログ記録を実装するフェーズです。

## 実装タスク

### 1. レート制限の実装

#### 1.1 レート制限ライブラリ

**選択肢**:
- **Bucket4j**: トークンバケットアルゴリズム
- **Resilience4j**: レート制限、サーキットブレーカーなど
- **Spring Cloud Gateway**: ゲートウェイレベルでの制限

**推奨**: Bucket4j（シンプルで十分）

#### 1.2 レート制限設定

**制限レベル**:
- **一般 API**: 100リクエスト/15分
- **認証 API**: 10リクエスト/15分（ログイン試行制限）
- **管理者 API**: 200リクエスト/15分

**実装方法**:
- `@RateLimiter` アノテーション（Resilience4j）
- または `Filter` で実装

**設定例**:
```yaml
rate-limit:
  general:
    max-requests: 100
    window-duration: 15m
  auth:
    max-requests: 10
    window-duration: 15m
  admin:
    max-requests: 200
    window-duration: 15m
```

#### 1.3 レート制限エラー

**レスポンス**:
- HTTP 429 (Too Many Requests)
- エラーメッセージ: "リクエストが多すぎます。しばらく待ってから再試行してください。"

---

### 2. リクエストサイズ制限

#### 2.1 サイズ制限設定

**制限項目**:
- JSON リクエストボディ: 1MB
- マルチパート（ファイルアップロード）: 10MB
- URL パラメータ: 2KB

**実装方法**:
- `application.yml` で設定
- `spring.servlet.multipart.max-file-size`
- `spring.servlet.multipart.max-request-size`

**設定例**:
```yaml
spring:
  servlet:
    multipart:
      max-file-size: 10MB
      max-request-size: 10MB
  http:
    encoding:
      max-request-size: 1MB
```

#### 2.2 サイズ超過エラー

**レスポンス**:
- HTTP 413 (Payload Too Large)
- エラーメッセージ: "リクエストサイズが大きすぎます。"

---

### 3. セキュリティヘッダー設定

#### 3.1 セキュリティヘッダー

**設定するヘッダー**:
- `X-Content-Type-Options: nosniff`
- `X-Frame-Options: DENY`
- `X-XSS-Protection: 1; mode=block`
- `Strict-Transport-Security: max-age=31536000`（HTTPS 時）
- `Content-Security-Policy: default-src 'self'`

**実装方法**:
- Spring Security の `HeadersConfigurer` を使用
- または `Filter` で実装

#### 3.2 SecurityConfig の更新

**設定内容**:
- セキュリティヘッダーの有効化
- カスタムヘッダーの追加

---

### 4. CORS 設定

#### 4.1 CORS 設定

**許可するオリジン**:
- 開発環境: `http://localhost:3000`, `http://localhost:3001`
- 本番環境: 環境変数から取得

**許可するメソッド**:
- GET, POST, PUT, DELETE, PATCH

**許可するヘッダー**:
- Content-Type, Authorization

**認証情報**:
- `credentials: true` で Cookie を含むリクエストを許可

**実装方法**:
- `CorsConfiguration` で設定
- `SecurityConfig` で適用

#### 4.2 CORS エラー

**エラーハンドリング**:
- CORS エラーはブラウザで自動的に処理
- サーバー側では適切な CORS ヘッダーを返す

---

### 5. リクエストタイムアウト

#### 5.1 タイムアウト設定

**タイムアウト時間**:
- リクエストタイムアウト: 30秒
- 接続タイムアウト: 10秒

**実装方法**:
- `@Async` を使用する場合は `@AsyncConfigurer` で設定
- HTTP リクエストの場合は `HttpClient` で設定

#### 5.2 タイムアウトエラー

**レスポンス**:
- HTTP 408 (Request Timeout)
- エラーメッセージ: "リクエストがタイムアウトしました。"

---

### 6. リクエスト監視・ログ記録

#### 6.1 リクエストログ

**記録項目**:
- リクエストメソッド、パス
- リクエスト元 IP アドレス
- ユーザーID（認証済みの場合）
- リクエスト時間
- レスポンスステータス
- 処理時間

**実装方法**:
- `HandlerInterceptor` を使用
- または `Filter` で実装

#### 6.2 ログレベル

**ログレベル**:
- 正常リクエスト: INFO
- エラーレスポンス: WARN
- セキュリティ関連: ERROR

#### 6.3 ログフォーマット

**フォーマット例**:
```
[2025-01-10 10:00:00] INFO  POST /api/orders - 200 OK - 150ms - User: 123 - IP: 192.168.1.1
```

## 注意事項

1. **レート制限**: 本番環境では Redis を使用した分散レート制限を検討
2. **ログ**: 機密情報（パスワード、トークン）はログに記録しない
3. **CORS**: 本番環境では許可するオリジンを厳密に設定
4. **セキュリティヘッダー**: すべてのレスポンスに設定
5. **タイムアウト**: 長時間実行される処理は非同期処理を検討
