# フェーズ 9: 最適化とテスト - 詳細設計書

## 概要

パフォーマンス最適化、データベースクエリ最適化、キャッシング戦略、単体テスト・統合テスト、負荷テスト、API ドキュメント生成を実装するフェーズです。

## 実装タスク

### 1. パフォーマンス最適化

#### 1.1 データベースクエリ最適化

**最適化項目**:
- N+1 問題の解決
- インデックスの追加
- クエリの最適化
- 遅延ロードの適切な使用

**実装方法**:
- `@EntityGraph` を使用して関連エンティティを一括取得
- `JOIN FETCH` を使用
- 必要に応じて `@BatchSize` を使用

**最適化対象**:
- 商品一覧取得（カテゴリ情報も含む）
- 注文詳細取得（注文アイテム、商品情報も含む）
- カート取得（商品情報も含む）

#### 1.2 インデックス追加

**追加するインデックス**:
- `foods.category_id`: カテゴリ検索
- `foods.status`: ステータスフィルタ
- `orders.user_id`: ユーザー別注文検索
- `orders.order_date`: 日付ソート
- `cart_items.cart_id`: カートアイテム取得

**実装方法**:
- `@Index` アノテーションでエンティティに定義
- またはマイグレーションファイルで追加

### 2. データベースクエリ最適化

#### 2.1 クエリ分析

**分析ツール**:
- Hibernate の SQL ログ
- `EXPLAIN` クエリの実行
- スロークエリログ

**最適化対象**:
- 頻繁に実行されるクエリ
- 処理時間が長いクエリ
- 大量データを扱うクエリ

#### 2.2 クエリ最適化手法

**手法**:
- 不要な `SELECT` を避ける（`@Query` で必要なフィールドのみ取得）
- `DISTINCT` の適切な使用
- サブクエリの最適化
- ページネーションの適切な実装

---

### 3. キャッシング戦略の実装

#### 3.1 キャッシング対象

**キャッシングするデータ**:
- カテゴリ一覧（変更頻度が低い）
- 商品一覧（一定時間キャッシュ）
- ユーザー情報（セッション中）

**キャッシングしないデータ**:
- 在庫情報（リアルタイム性が重要）
- 注文情報（整合性が重要）

#### 3.2 キャッシング実装

**実装方法**:
- Spring Cache (`@Cacheable`, `@CacheEvict`)
- ローカルキャッシュ（Caffeine）または分散キャッシュ（Redis）

**キャッシュ設定**:
- TTL: カテゴリ 1時間、商品一覧 5分
- キャッシュキー: 適切なキー設計

#### 3.3 キャッシュ無効化

**無効化タイミング**:
- 商品作成・更新・削除時
- カテゴリ作成・更新・削除時

**実装方法**:
- `@CacheEvict` アノテーションを使用

### 4. 単体テスト・統合テスト

#### 4.1 単体テスト

**テスト対象**:
- Service 層のビジネスロジック
- Utility クラス
- Mapper クラス

**テストフレームワーク**:
- JUnit 5
- Mockito（モック作成）

**テストカバレッジ目標**:
- 80% 以上

#### 4.2 統合テスト

**テスト対象**:
- Controller 層
- Repository 層
- データベース連携

**テストフレームワーク**:
- Spring Boot Test
- Testcontainers（PostgreSQL コンテナ）

**テスト内容**:
- API エンドポイントの動作確認
- データベース操作の確認
- トランザクション処理の確認

#### 4.3 テストデータ

**データ準備**:
- `@Sql` アノテーションでテストデータ投入
- または `@BeforeEach` でデータ準備

### 5. 負荷テスト

#### 5.1 負荷テストツール

**選択肢**:
- **JMeter**: GUI ベース、機能豊富
- **Gatling**: Scala ベース、高パフォーマンス
- **K6**: JavaScript ベース、モダン

**推奨**: JMeter（使いやすい）

#### 5.2 テストシナリオ

**シナリオ**:
- 商品一覧取得（高頻度）
- 商品検索（中頻度）
- カート操作（中頻度）
- 注文作成（低頻度）

**負荷設定**:
- 同時ユーザー数: 100, 500, 1000
- テスト時間: 5分、10分、30分

#### 5.3 パフォーマンス指標

**測定項目**:
- レスポンスタイム（平均、最大、95パーセンタイル）
- スループット（リクエスト/秒）
- エラー率
- CPU 使用率
- メモリ使用率

**目標値**:
- 平均レスポンスタイム: 200ms 以下
- 95パーセンタイル: 500ms 以下
- エラー率: 1% 以下

---

### 6. API ドキュメント生成

#### 6.1 API ドキュメントツール

**選択肢**:
- **SpringDoc OpenAPI**: Spring Boot 統合、Swagger UI
- **Swagger**: 標準的な API ドキュメント

**推奨**: SpringDoc OpenAPI

#### 6.2 API ドキュメント設定

**依存関係**:
```xml
<dependency>
    <groupId>org.springdoc</groupId>
    <artifactId>springdoc-openapi-starter-webmvc-ui</artifactId>
    <version>2.3.0</version>
</dependency>
```

**設定**:
- `application.yml` で OpenAPI 設定
- `@Operation`, `@ApiResponse` アノテーションで詳細を記述

#### 6.3 API ドキュメント内容

**記載内容**:
- エンドポイント一覧
- リクエスト・レスポンス形式
- 認証方法
- エラーコード一覧
- サンプルリクエスト・レスポンス

**アクセス**:
- Swagger UI: `http://localhost:5000/swagger-ui.html`
- OpenAPI JSON: `http://localhost:5000/v3/api-docs`
