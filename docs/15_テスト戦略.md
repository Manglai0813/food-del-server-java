# テスト戦略

## 概要

Java 21 + Spring Boot 3 プロジェクトのテスト戦略と実装ガイドを説明するドキュメントです。

## テストの種類

### 1. 単体テスト（Unit Test）

**対象**: Service 層のビジネスロジック

**目的**: 個別のメソッドやクラスの動作を検証

**ツール**: JUnit 5, Mockito

### 2. 統合テスト（Integration Test）

**対象**: Controller 層、Repository 層、データベース連携

**目的**: 複数のコンポーネントの連携を検証

**ツール**: Spring Boot Test, Testcontainers

---

## 単体テスト

### 1. Service 層のテスト

#### 1.1 テストクラスの作成

**命名規則**: `{ServiceName}Test`

**例**: `UserServiceTest`, `OrderServiceTest`

#### 1.2 モックの使用

**依存関係のモック化**:
- Repository を Mockito でモック
- 外部サービスをモック

**例**:
```java
@ExtendWith(MockitoExtension.class)
class UserServiceTest {
    @Mock
    private UserRepository userRepository;
    
    @InjectMocks
    private UserServiceImpl userService;
    
    @Test
    void should_CreateUser_When_ValidRequest() {
        // Given
        CreateUserRequest request = new CreateUserRequest(...);
        User savedUser = new User(...);
        when(userRepository.save(any(User.class))).thenReturn(savedUser);
        
        // When
        UserResponse result = userService.createUser(request);
        
        // Then
        assertThat(result).isNotNull();
        assertThat(result.getEmail()).isEqualTo(request.getEmail());
        verify(userRepository).save(any(User.class));
    }
}
```

## 統合テスト

### 1. Repository 層のテスト

#### 1.1 テストデータベース

**選択肢**:
- **H2 インメモリデータベース**: 高速、簡単
- **Testcontainers**: 実際の PostgreSQL コンテナ

**推奨**: Testcontainers（本番環境に近い）

---

### 2. Controller 層のテスト

#### 2.1 MockMvc を使用

**例**:
```java
@WebMvcTest(UserController.class)
class UserControllerTest {
    @Autowired
    private MockMvc mockMvc;
    
    @MockBean
    private UserService userService;
    
    @Test
    void should_ReturnUser_When_ValidRequest() throws Exception {
        // Given
        UserResponse userResponse = new UserResponse(...);
        when(userService.getUserProfile(anyLong())).thenReturn(userResponse);
        
        // When & Then
        mockMvc.perform(get("/api/users/profile")
                .header("Authorization", "Bearer token"))
                .andExpect(status().isOk())
                .andExpect(jsonPath("$.success").value(true));
    }
}
```

## テストのベストプラクティス

### 1. テストの独立性

**規則**: テストは互いに独立していること

### 2. テストの可読性

**規則**: テスト名は意図を明確に表現

**例**:
- `should_ReturnUser_When_ValidIdProvided()`
- `should_ThrowException_When_UserNotFound()`

### 3. AAA パターン

**構造**: Arrange（準備）→ Act（実行）→ Assert（検証）
