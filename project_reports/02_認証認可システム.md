## 1. 概要

### 1.1 認証・認可とは

**認証 (Authentication)**

- ユーザーが誰であるかを確認するプロセス
- 例: ログイン時にメールアドレスとパスワードで本人確認

**認可 (Authorization)**

- 認証されたユーザーが何をできるかを決定するプロセス
- 例: 管理者のみが商品を削除できる

### 1.2 本システムの認証方式

本プロジェクトは **JWT (JSON Web Token)** ベースの認証を採用しています。

**JWTの特徴**:

- ✅ **ステートレス**: サーバー側でセッション情報を保持しない
- ✅ **スケーラブル**: 水平拡張が容易
- ✅ **モバイルフレンドリー**: クロスドメイン対応
- ✅ **自己完結型**: トークン内に必要な情報を含む

## 2. JWT認証メカニズム

### 2.1 JWTの構造

JWTは3つの部分で構成されます：

```
eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiJ1c2VyQGV4YW1wbGUuY29tIiwicm9sZSI6IlVTRVIifQ.SflKxwRJSMeKKF2QT4fwpMeJf36POk6yJV_adQssw5c
    ↑ Header                           ↑ Payload                                  ↑ Signature
```

#### Header (ヘッダー)

```json
{
  "alg": "HS256",
  "typ": "JWT"
}
```

- `alg`: 署名アルゴリズム（HS256 = HMAC SHA-256）
- `typ`: トークンタイプ

#### Payload (ペイロード)

```json
{
  "sub": "user@example.com",
  "role": "USER",
  "userId": 1,
  "iat": 1700000000,
  "exp": 1700086400,
  "jti": "uuid-here"
}
```

- `sub`: Subject（ユーザー識別子、通常はメールアドレス）
- `role`: ユーザーロール
- `userId`: ユーザーID
- `iat`: Issued At（発行時刻）
- `exp`: Expiration（有効期限）
- `jti`: JWT ID（トークンの一意識別子）

#### Signature (署名)

```
HMACSHA256(
  base64UrlEncode(header) + "." + base64UrlEncode(payload),
  secret
)
```

### 2.2 Access Token vs Refresh Token

本システムは**2種類のトークン**を使用します：

| トークン | 有効期限 | 用途 | 保存場所 |
|---------|---------|------|---------|
| **Access Token** | 24時間 | API呼び出し | ローカルストレージ/メモリ |
| **Refresh Token** | 7日間 | Access Token更新 | データベース |

**なぜ2種類？**

- Access Tokenは短命 → セキュリティ向上
- Refresh Tokenで更新 → ユーザー体験向上

### 2.3 トークン生成ロジック

#### Access Token生成

[`JwtUtil.java`](file:///home/manglai/Projects/food-del-server-java/src/main/java/com/fooddel/security/jwt/JwtUtil.java#L39-L47)

```java
public String generateToken(UserDetails userDetails) {
    Map<String, Object> claims = new HashMap<>();
    if (userDetails instanceof User) {
        claims.put("role", ((User) userDetails).getRole());
        claims.put("userId", ((User) userDetails).getId());
    }
    return doGenerateToken(claims, userDetails.getUsername(), 
                          JWT_ACCESS_TOKEN_VALIDITY, getAccessSigningKey());
}
```

**ポイント**:

- ユーザーロールとIDをクレームに追加
- 有効期限: 24時間
- 署名キー: `app.jwt.secret`

#### Refresh Token生成

```java
public String generateRefreshToken(UserDetails userDetails) {
    // リフレッシュトークンには最小限の情報のみ
    return doGenerateToken(new HashMap<>(), userDetails.getUsername(), 
                          JWT_REFRESH_TOKEN_VALIDITY, getRefreshSigningKey());
}
```

**ポイント**:

- 最小限の情報のみ（セキュリティ向上）
- 有効期限: 7日間
- 署名キー: `app.jwt.refresh-secret`

### 2.4 トークン検証ロジック

```java
public Boolean validateToken(String token, UserDetails userDetails) {
    final String username = extractUsername(token);
```

**検証項目**:

1. ユーザー名が一致するか
2. トークンが期限切れでないか
3. 署名が正しいか（自動検証）

## 3. Spring Security設定

### 3.1 SecurityConfig概要

[`SecurityConfig.java`](file:///home/manglai/Projects/food-del-server-java/src/main/java/com/fooddel/config/security/SecurityConfig.java)

```java
@Configuration
@EnableWebSecurity
public class SecurityConfig {
    
    @Bean
    public SecurityFilterChain securityFilterChain(HttpSecurity http, 
                                                   JwtAuthFilter jwtAuthFilter) {
        http
            .csrf(AbstractHttpConfigurer::disable)  // CSRF無効化
            .cors(cors -> cors.configurationSource(corsConfigurationSource()))
            .authorizeHttpRequests(authorize -> authorize
                .requestMatchers("/api/auth/**").permitAll()  // 認証エンドポイントは公開
                .requestMatchers("/swagger-ui/**", "/v3/api-docs/**").permitAll()  // Swagger公開
                .anyRequest().authenticated()  // その他は認証必要
            )
            .sessionManagement(session -> 
                session.sessionCreationPolicy(SessionCreationPolicy.STATELESS))  // ステートレス
            .addFilterBefore(jwtAuthFilter, UsernamePasswordAuthenticationFilter.class);
        
        return http.build();
    }
}
```

### 3.3 JwtAuthFilter実装

[`JwtAuthFilter.java`](file:///home/manglai/Projects/food-del-server-java/src/main/java/com/fooddel/config/security/JwtAuthFilter.java)

```java
@Component
public class JwtAuthFilter extends OncePerRequestFilter {
    
    @Override
    protected void doFilterInternal(HttpServletRequest request,
                                    HttpServletResponse response,
                                    FilterChain filterChain) {
        // 1. Authorizationヘッダーからトークン抽出
        String authHeader = request.getHeader("Authorization");
        if (authHeader != null && authHeader.startsWith("Bearer ")) {
            String jwt = authHeader.substring(7);
            String username = jwtUtil.extractUsername(jwt);
            
            // 2. トークンブラックリストチェック
            if (!tokenBlacklistService.isBlacklisted(jwt)) {
                // 3. ユーザー情報取得
                UserDetails userDetails = userDetailsService.loadUserByUsername(username);
                
                // 4. トークン検証
                if (jwtUtil.validateToken(jwt, userDetails)) {
                    // 5. SecurityContextに認証情報設定
                    UsernamePasswordAuthenticationToken authToken = 
                        new UsernamePasswordAuthenticationToken(
                            userDetails, null, userDetails.getAuthorities());
                    SecurityContextHolder.getContext().setAuthentication(authToken);
                }
            }
        }
        
        filterChain.doFilter(request, response);
    }
}
```

**処理フロー**:

1. Authorizationヘッダーからトークン抽出
2. ブラックリストチェック
3. ユーザー情報取得
4. トークン検証
5. SecurityContextに認証情報設定

## 5. トークンブラックリスト

### 5.1 なぜブラックリストが必要？

JWTはステートレスなため、**サーバー側で無効化できない**という問題があります。

**問題シナリオ**:

1. ユーザーがログイン → Access Token取得
2. ユーザーがログアウト
3. **しかし、トークンはまだ有効期限内**
4. 悪意のある第三者がトークンを使用可能 ❌

**解決策**: ログアウト時にトークンをブラックリストに追加

### 5.2 実装

[`TokenBlacklistService.java`](file:///home/manglai/Projects/food-del-server-java/src/main/java/com/fooddel/security/TokenBlacklistService.java)

```java
@Service
public class TokenBlacklistService {
    
    @Autowired
    private RedisTemplate<String, String> redisTemplate;
    
    // トークンをブラックリストに追加
    public void blacklistToken(String jti, long expirationTime) {
        String key = "blacklist:" + jti;
        long ttl = expirationTime - System.currentTimeMillis();
        
        if (ttl > 0) {
            redisTemplate.opsForValue().set(key, "blacklisted", 
                                           ttl, TimeUnit.MILLISECONDS);
        }
    }
    
    // ブラックリストチェック
    public boolean isBlacklisted(String jti) {
        String key = "blacklist:" + jti;
        return Boolean.TRUE.equals(redisTemplate.hasKey(key));
    }
}
```

**Redis構造**:

```
Key: blacklist:<jti>
Value: "blacklisted"
TTL: トークンの残り有効期限
```

**利点**:

- ✅ メモリ効率的（TTL自動削除）
- ✅ 高速チェック（Redis）
- ✅ スケーラブル

## 6. セキュリティベストプラクティス

### 6.1 パスワードセキュリティ

#### BCrypt暗号化

```java
@Bean
public static PasswordEncoder passwordEncoder() {
    return new BCryptPasswordEncoder();
}

// 使用例
String hashedPassword = passwordEncoder.encode("plainPassword");
boolean matches = passwordEncoder.matches("plainPassword", hashedPassword);
```

**BCryptの特徴**:

- ✅ ソルト自動生成
- ✅ 計算コスト調整可能
- ✅ レインボーテーブル攻撃に強い

#### パスワードポリシー（推奨）

```java
@NotBlank(message = "パスワードは必須です")
@Size(min = 8, message = "パスワードは8文字以上必要です")
@Pattern(regexp = "^(?=.*[a-z])(?=.*[A-Z])(?=.*\\d).*$", 
         message = "パスワードは大文字、小文字、数字を含む必要があります")
private String password;
```

### 6.2 トークンセキュリティ

#### シークレットキー管理

```yaml
# application.yml
app:
  jwt:
    secret: ${JWT_SECRET:your-256-bit-secret-key-here}
    refresh-secret: ${JWT_REFRESH_SECRET:your-256-bit-refresh-secret-key-here}
```

**ベストプラクティス**:

- ✅ 環境変数から読み込み
- ✅ 本番環境では必ず変更
- ✅ 256ビット以上の長さ
- ✅ ランダム生成

#### トークン保存場所

| 保存場所 | セキュリティ | 推奨度 |
|---------|------------|--------|
| LocalStorage | ❌ XSS脆弱 | 非推奨 |
| SessionStorage | ❌ XSS脆弱 | 非推奨 |
| Cookie (HttpOnly) | ✅ XSS保護 | 推奨 |
| メモリ | ✅ 最も安全 | 推奨（SPA） |

## 7. トラブルシューティング

### 7.1 よくある問題

#### 問題1: "Token has expired"

**原因**: Access Tokenの有効期限切れ

**解決策**:

```javascript
// フロントエンド実装例
if (error.response.status === 401 && error.response.data.code === "TOKEN_EXPIRED") {
    // Refresh Tokenで更新
    const newToken = await refreshAccessToken();
    // リクエスト再試行
}
```

#### 問題2: "Invalid signature"

**原因**: シークレットキーの不一致

**解決策**:

- `application.yml`のシークレットキーを確認
- 環境変数が正しく設定されているか確認

#### 問題3: ログアウト後もAPIアクセス可能

**原因**: ブラックリストが機能していない

**解決策**:

- Redisが起動しているか確認
- `TokenBlacklistService`が正しく呼ばれているか確認
