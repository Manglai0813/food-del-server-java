## 1. 概要

### 1.1 在庫管理の課題

ECサイトにおける在庫管理の最大の課題は**過剰販売（Overselling）の防止**です。

**問題シナリオ**:

```
在庫: 10個

ユーザーA: カートに5個追加
ユーザーB: カートに7個追加
合計: 12個 > 10個 ❌ 過剰販売！
```

### 1.2 本システムの解決策

本プロジェクトは**在庫予約メカニズム**を採用しています。

**基本概念**:

- `stock`: 実在庫数
- `reserved`: 予約済み在庫数
- **利用可能在庫** = `stock - reserved`

**フィールド説明**:

- `stock`: 物理的な在庫数
- `reserved`: カートに入っている数（まだ購入されていない）
- `minStock`: 在庫アラートの閾値
- `version`: 楽観的ロック用バージョン番号

### 2.2 在庫状態の計算

```java
// 利用可能在庫
int availableStock = food.getStock() - food.getReserved();

// 在庫チェック
if (availableStock < requestedQuantity) {
    throw new BusinessException("在庫が不足しています");
}
```

**例**:

```
stock = 100
reserved = 30
利用可能 = 100 - 30 = 70個
```

## 3. 並行制御

### 3.1 楽観的ロック (Optimistic Locking)

#### 仕組み

```java
@Entity
public class Food {
    @Version
    private Long version;  // 自動管理
}
```

**動作フロー**:

```
1. データ読み込み: { id: 1, stock: 100, version: 5 }
2. 在庫更新: stock = 95
3. 保存時にバージョンチェック:
   UPDATE food SET stock = 95, version = 6 
   WHERE id = 1 AND version = 5
4. 他のトランザクションが先に更新していた場合:
   → version != 5 → OptimisticLockException
```

**利点**:

- ✅ 高性能（ロック不要）
- ✅ デッドロック回避
- ✅ 読み取り競合なし

**欠点**:

- ❌ 更新競合時に例外
- ❌ リトライ処理が必要

#### 使用場所

- カート操作（競合少ない）
- 商品情報更新

### 3.2 悲観的ロック (Pessimistic Locking)

#### 仕組み

[`FoodRepository.java`](file:///home/manglai/Projects/food-del-server-java/src/main/java/com/fooddel/repository/FoodRepository.java)

```java
@Lock(LockModeType.PESSIMISTIC_WRITE)
@Query("SELECT f FROM Food f WHERE f.id = :id")
Optional<Food> findByIdWithLock(@Param("id") Integer id);
```

**動作フロー**:

```
1. SELECT ... FOR UPDATE
   → データベースレベルでロック取得
2. 他のトランザクションは待機
3. 更新完了後、ロック解放
```

**利点**:

- ✅ 確実な排他制御
- ✅ 競合時の例外なし
- ✅ 複雑なロジックに適用可能

**欠点**:

- ❌ パフォーマンス低下
- ❌ デッドロックリスク

#### 使用場所

- **注文作成時**（在庫扣減）
- 重要な在庫操作

**コード**:

```java
@Transactional
public Cart addItemToCart(Integer userId, CartItemRequest request) {
    Food food = foodRepository.findById(request.getFoodId())
        .orElseThrow(() -> new BusinessException("商品が見つかりません"));
    
    // 在庫チェック（予約分も考慮）
    if ((food.getStock() - food.getReserved()) < request.getQuantity()) {
        throw new BusinessException("在庫が不足しています");
    }
    
    // カートに追加
    CartItem item = new CartItem();
    item.setFood(food);
    item.setQuantity(request.getQuantity());
    cart.getCartItems().add(item);
    
    // 予約数を更新
    food.setReserved(food.getReserved() + request.getQuantity());
    foodRepository.save(food);
    
    return cartRepository.save(cart);
}
```

**ポイント**:

- ✅ 利用可能在庫をチェック
- ✅ 予約数を即座に増やす
- ✅ トランザクション内で処理

### 4.2 カート数量更新

[`CartServiceImpl.updateItemInCart()`](file:///home/manglai/Projects/food-del-server-java/src/main/java/com/fooddel/service/impl/CartServiceImpl.java#L92-L115)

```java
@Transactional
public Cart updateItemInCart(Integer userId, Integer cartItemId, 
                             CartItemRequest request) {
    CartItem cartItem = findCartItemInCart(cart, cartItemId);
    
    int oldQuantity = cartItem.getQuantity();
    int newQuantity = request.getQuantity();
    int diff = newQuantity - oldQuantity;  // 差分計算
    
    Food food = cartItem.getFood();
    
    // 増える場合のみ在庫チェック
    if (diff > 0) {
        if ((food.getStock() - food.getReserved()) < diff) {
            throw new BusinessException("在庫が不足しています");
        }
    }
    
    // 予約数を更新（差分のみ）
    food.setReserved(food.getReserved() + diff);
    foodRepository.save(food);
    
    cartItem.setQuantity(newQuantity);
    return cartRepository.save(cart);
}
```

**ポイント**:

- ✅ 差分のみ計算（効率的）
- ✅ 減る場合は在庫チェック不要
- ✅ 予約数を差分で調整

```java
@Transactional
public Order createOrder(Integer userId, OrderRequest orderRequest) {
    Cart cart = cartService.getCartByUserId(userId);
    
    List<OrderItem> orderItems = new ArrayList<>();
    BigDecimal totalAmount = BigDecimal.ZERO;
    
    for (CartItem cartItem : cart.getCartItems()) {
        // 悲観的ロックで商品を取得
        Food food = foodRepository.findByIdWithLock(cartItem.getFood().getId())
            .orElseThrow(() -> new BusinessException("商品が見つかりません"));
        
        // 在庫チェック
        if (food.getStock() < cartItem.getQuantity()) {
            throw new BusinessException("在庫不足です: " + food.getName());
        }
        
        // 注文アイテムを作成
        OrderItem orderItem = new OrderItem();
        orderItem.setFood(food);
        orderItem.setQuantity(cartItem.getQuantity());
        orderItem.setPrice(food.getPrice());
        orderItems.add(orderItem);
        
        // 合計金額を計算
        totalAmount = totalAmount.add(
            food.getPrice().multiply(BigDecimal.valueOf(cartItem.getQuantity()))
        );
        
        // 在庫を更新（実在庫から減算）
        food.setStock(food.getStock() - cartItem.getQuantity());
        // 予約を解除（カートに入れた時に予約していた分を解除）
        food.setReserved(food.getReserved() - cartItem.getQuantity());
        foodRepository.save(food);
    }
    
    // 注文を作成
    Order order = new Order();
    order.setUser(user);
    order.setTotalAmount(totalAmount);
    order.setStatus(OrderStatus.PENDING);
    order.setOrderItems(orderItems);
    
    Order savedOrder = orderRepository.save(order);
    
    // カートをクリア
    cartService.clearCart(userId);
    
    return savedOrder;
}
```

**重要ポイント**:

1. ✅ **悲観的ロック**で確実に排他制御
2. ✅ **実在庫を減らす**: `stock -= quantity`
3. ✅ **予約を解除**: `reserved -= quantity`
4. ✅ トランザクション内で全て処理

```java
@Transactional
public Order cancelOrder(Integer userId, Integer orderId) {
    Order order = findOrderById(orderId)
        .orElseThrow(() -> new BusinessException("注文が見つかりません"));
    
    // ステータスチェック
    if (order.getStatus() != OrderStatus.PENDING) {
        throw new BusinessException("この注文はキャンセルできません");
    }
    
    // 在庫を返却
    for (OrderItem item : order.getOrderItems()) {
        Food food = item.getFood();
        food.setStock(food.getStock() + item.getQuantity());
        foodRepository.save(food);
    }
    
    // 注文ステータスを更新
    order.setStatus(OrderStatus.CANCELLED);
    return orderRepository.save(order);
}
```

**ポイント**:

- ✅ 在庫を返却
- ✅ 予約は解除しない（既に注文時に解除済み）

## 5. エッジケース処理

### 5.1 ケース1: カートに入れたまま放置

**問題**:

```
ユーザーA: 商品を10個カートに追加
         → reserved = 10
         → そのまま放置（購入しない）
         → 他のユーザーが購入できない
```

**解決策（推奨）**:

```java
// カートアイテムにタイムスタンプを追加
@Entity
public class CartItem {
    @CreatedDate
    private LocalDateTime createdAt;
}

// 定期的に古いカートアイテムをクリア
@Scheduled(cron = "0 0 * * * *")  // 1時間ごと
public void clearExpiredCartItems() {
    LocalDateTime threshold = LocalDateTime.now().minusHours(24);
    List<CartItem> expiredItems = cartItemRepository
        .findByCreatedAtBefore(threshold);
    
    for (CartItem item : expiredItems) {
        // 予約を解除
        Food food = item.getFood();
        food.setReserved(food.getReserved() - item.getQuantity());
        foodRepository.save(food);
        
        // カートアイテムを削除
        cartItemRepository.delete(item);
    }
}
```

### 5.2 ケース2: 並行注文

**問題**:

```
在庫: 10個
ユーザーA: 10個注文 → 処理中
ユーザーB: 10個注文 → 処理中
両方成功 → 20個販売 ❌
```

**解決策**: 悲観的ロック

```java
// SELECT ... FOR UPDATE
Food food = foodRepository.findByIdWithLock(id);
// → ユーザーBはユーザーAの処理完了まで待機
```

### 5.3 ケース3: 楽観的ロック競合

**問題**:

```
ユーザーA: 商品情報を読み込み (version = 5)
ユーザーB: 商品情報を読み込み (version = 5)
ユーザーA: 更新 (version = 6) → 成功
ユーザーB: 更新 (version = 6) → 失敗（version != 5）
```

**解決策**: リトライ処理

```java
@Retryable(
    value = OptimisticLockException.class,
    maxAttempts = 3,
    backoff = @Backoff(delay = 100)
)
public void updateFood(Integer id, FoodRequest request) {
    // 更新処理
}
```
