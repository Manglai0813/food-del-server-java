## 1. 起動時の問題

### 問題1: アプリケーションが起動しない

**エラーメッセージ**:

```
Failed to configure a DataSource
```

**原因**: データベース接続設定が正しくない

**解決策**:

```yaml
# application.yml を確認
spring:
  datasource:
    url: jdbc:postgresql://localhost:5432/fooddb
    username: your_username
    password: your_password
```

### 問題2: ポート5000が使用中

**エラーメッセージ**:

```
Port 5000 is already in use
```

**解決策**:

```bash
# ポートを使用しているプロセスを確認
lsof -i :5000

# プロセスを終了
kill -9 <PID>

# または、別のポートを使用
server:
  port: 8080
```

## 2. 認証関連の問題

### 問題1: "Token has expired"

**原因**: Access Tokenの有効期限切れ

**解決策**:

```javascript
// フロントエンド実装例
async function apiCall() {
  try {
    const response = await fetch('/api/foods', {
      headers: {
        'Authorization': `Bearer ${accessToken}`
      }
    });
    return response.json();
  } catch (error) {
    if (error.response?.status === 401) {
      // Refresh Tokenで更新
      const newToken = await refreshAccessToken();
      // リクエスト再試行
      return apiCall();
    }
  }
}
```

### 問題2: "Invalid signature"

**原因**: JWTシークレットキーの不一致

**解決策**:

```yaml
# application.yml を確認
app:
  jwt:
    secret: ${JWT_SECRET:your-256-bit-secret-key}
    refresh-secret: ${JWT_REFRESH_SECRET:your-refresh-secret-key}
```

**環境変数で設定**:

```bash
export JWT_SECRET="your-secret-key-here"
export JWT_REFRESH_SECRET="your-refresh-secret-key-here"
```

### 問題3: ログアウト後もAPIアクセス可能

**原因**: トークンブラックリストが機能していない

**確認事項**:

1. Redisが起動しているか

```bash
redis-cli ping
# 応答: PONG
```

2. Redis接続設定

```yaml
spring:
  data:
    redis:
      host: localhost
      port: 6379
```

## 3. 在庫関連の問題

### 問題1: 在庫が負の値になる

**原因**: 並行処理での競合

**確認方法**:

```sql
SELECT id, name, stock, reserved 
FROM food 
WHERE stock < 0 OR reserved < 0;
```

**解決策**: 悲観的ロックが正しく動作しているか確認

```java
// FoodRepository.findByIdWithLock() を使用しているか確認
Food food = foodRepository.findByIdWithLock(id);
```

### 問題2: 予約数が在庫を超える

**原因**: 在庫チェックロジックの不備

**確認方法**:

```sql
SELECT id, name, stock, reserved 
FROM food 
WHERE reserved > stock;
```

**解決策**: CHECK制約を追加

```sql
ALTER TABLE food 
ADD CONSTRAINT chk_reserved_stock 
CHECK (reserved <= stock);
```

### 問題3: カートに追加できない

**エラー**: "在庫が不足しています"

**確認方法**:

```sql
SELECT id, name, stock, reserved, (stock - reserved) as available
FROM food
WHERE id = ?;
```

**解決策**:

- 利用可能在庫を確認
- 予約が正しく解除されているか確認

## 4. データベース関連の問題

### 問題1: "Optimistic lock exception"

**原因**: 楽観的ロックの競合

**解決策**: リトライ処理を実装

```java
@Retryable(
    value = OptimisticLockException.class,
    maxAttempts = 3,
    backoff = @Backoff(delay = 100)
)
public void updateFood(Integer id, FoodRequest request) {
    // 更新処理
}
```

### 問題2: "Deadlock detected"

**原因**: 複数のトランザクションが互いにロック待ち

**確認方法**:

```sql
-- PostgreSQL
SELECT * FROM pg_stat_activity 
WHERE state = 'active';
```

**解決策**:

- トランザクションを短く保つ
- ロック順序を統一する
- タイムアウトを設定

### 問題3: データベース接続プールが枯渇

**エラー**: "Unable to acquire JDBC Connection"

**解決策**:

```yaml
spring:
  datasource:
    hikari:
      maximum-pool-size: 20
      minimum-idle: 5
      connection-timeout: 30000
```

## 5. ログの確認方法

### 5.1 アプリケーションログ

```bash
# ログファイルを確認
tail -f logs/food-del-server.log

# エラーのみ表示
grep "ERROR" logs/food-del-server.log

# 特定の日時のログ
grep "2024-01-01" logs/food-del-server.log
```

### 5.2 ログレベルの変更

```yaml
# application.yml
logging:
  level:
    com.fooddel: DEBUG
    org.springframework.security: DEBUG
    org.hibernate.SQL: DEBUG
```

### 5.3 データベースクエリログ

```yaml
spring:
  jpa:
    show-sql: true
    properties:
      hibernate:
        format_sql: true
```

## 6. パフォーマンス問題

### 問題1: APIレスポンスが遅い

**確認方法**:

```bash
# レスポンスタイムを測定
curl -w "@curl-format.txt" -o /dev/null -s http://localhost:5000/api/foods
```

**解決策**:

1. データベースクエリを確認
2. N+1問題をチェック
3. インデックスを追加
4. キャッシュを導入

### 問題2: メモリ使用量が高い

**確認方法**:

```bash
# JVMメモリ使用状況
jstat -gc <pid>
```

**解決策**:

```bash
# JVMオプションを調整
java -Xms512m -Xmx1024m -jar app.jar
```
